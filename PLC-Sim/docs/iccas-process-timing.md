# ICCAS 后处理工艺时长仿真

新模式按配方阶段和设备节拍估计累计工艺时间，再除以时间倍率。用途是排程、忙闲占用和
协议演示，不代表已经验证聚酰亚胺工艺完成、清洗合格或气泡消除。

## 启用 60 倍速

先在原终端用 Ctrl+C 停止占用 4855/4856 的旧 ICCAS 模拟器，再从工作区根目录运行：

```bash
./PLC-Sim/PLC-Sim/start_iccas_process.command
```

Windows 使用 `start_iccas_process.bat`。新入口仅启动喷雾与过滤除泡，端点仍为
`opc.tcp://127.0.0.1:4855/iccas_sim/` 和 `opc.tcp://127.0.0.1:4856/iccas_sim/`。
Prosys Browser 可使用原连接。新入口启用过滤扩展，预置演示配方，保存状态文件到
`PLC-Sim/PLC-Sim/data/runtime/iccas-process-state.json`。不会自动结束其他已运行进程。

等价 Python 命令：

```bash
python iccas_sim.py --station postprocessing --timing-mode process --time-scale 60 \
  --seed-process-recipe --filter-extensions --state-file /tmp/iccas-process-state.json
```

旧的 `start_iccas.command` 和 `plc-sim iccas` 默认仍是握手联调模式，已有自动化测试
不改变节拍。`--timing-mode process` 本身不预置配方；`--seed-process-recipe` 仅在本地
服务开始监听前写入演示时间参数，客户端随后可覆盖。明确写入的 0 不会被默认配方替换。
默认配方只预置计时相关字段，不预置满仓、罐号或一份用于实机的完整工艺配方。

## 时间模型

| 动作 | 工艺时间构成 | 预置配方在 60 倍速下 |
| --- | --- | --- |
| 单次取料/放料 | 估计搬运定位 30 秒 | 0.5 秒 |
| 喷雾后处理 | 加水 + 每次抽原液的喷雾周期 + 熟化 + 首次过滤 + 各洗涤组加水/搅拌/过滤 | 约 356.67 秒 |
| 搅拌桨清洗 | 各溶剂加液/等待/抽废 × 次数 + 吹扫 | 约 2.08 秒 |
| 移液针清洗 | 无配方点，使用估计 180 秒 | 3 秒 |
| 抽原液启动 | 抽原液/过滤 1200 秒 + 吹气 30 秒 | 20.5 秒 |
| 过滤站各项清洗 | 溶剂吸液 × 次数 + 吹气 + 对应抽废/进废/排废时间；原液管另加管路吹气及抽液 | 随各项配方累计 |
| 真空箱除泡 | 估计抽真空 180 秒 + 保持 7920 秒 + 配方泄压时间 | 135 秒 |

喷雾默认熟化为 300 分钟，洗涤搅拌为 5 分钟/轮、第一组 1 轮；这些时间取自当前
ICCAS 驱动默认值，不宣称已经过实验确认。喷雾合计 21,400 工艺秒中包含：
50 秒加水、600 秒喷雾、18,000 秒熟化、1200 秒首次过滤、50 秒洗涤加水、300 秒搅拌、
1200 秒洗涤过滤。A/B 分别读取对应参数，不共享计时。

当前洗涤组显示各项循环累计时长，未模拟每一轮内的机械细分步骤。喷雾进料未提供批量
体积/流量点，因此暂按“抽原液次数 × 600 秒”估计；不可将此理解为实测流量。
过滤清洗中的“吸液时间上限”和“抽废时间上限”按保守时间预算使用，状态中标为估计，
并非实测结束时刻。如果吸液上限为 0，则用体积/估计流量估算吸液时间。

## 调整假设与观测

可在 `config/iccas_timing.yaml` 调整 30 秒搬运、10 ml/s 加液、600 秒喷雾周期、
1200 秒喷雾过滤、180 秒抽真空等假设，也可用 `--timing-profile /path/to/profile.yaml`
指定独立配置。全部估计必须为有限正数；节点中的时间/液量/次数必须为有限非负数。
调整文件在重启后生效；当前进程不会热加载。

状态 JSON 提供每个通道的 `process_duration_s`、`wall_duration_s`、`timing_stages`、
`current_stage`、`remaining_wall_s` 和 `progress`。`source` 区分 `recipe_ms` 与各类
`estimated_*` / `time_limit_estimate`。这些字段不增加或改变供应商 OPC UA 点表。
进度是时间预算进度，不是物理完成度；即使时间进度达到 1，`hang` 注入仍不会完成。

时间计划在 Trigger 被接受时固定。中途修改参数只影响下一次请求。Trigger 提前拉低
取消模拟动作；Complete 在全部阶段计时结束后拉高，直到 Trigger 复位。
只改倍率会同时加速搬运，因而 30 秒搬运在 60 倍速下仍只有 0.5 秒，这是统一倍率的结果。

**客户端超时必须覆盖加速后的复合动作时长。** 当前演示喷雾约 357 秒，使用 ICCAS
驱动联调时请将喷雾设备配置 `action_timeout` 设为至少 600 秒；更长配方或更慢倍率需
继续增加。原有 120 秒超时会主动撤销动作，不能解释成工艺提前结束。

Prosys 外部代理也支持 `iccas_prosys.py run --timing-mode process --time-scale 60`；
它不自动向 Prosys 写入演示配方，应由客户端设置。该模式没有重启或修改本机 Prosys。

测试覆盖 60 倍换算、所有后处理通道、A/B 独立计划、触发后参数锁定、零循环、非法时间、
阶段进度、真实 OPC UA 延时与完成复位，并保留原来的握手模式回归测试。
